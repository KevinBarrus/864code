# 第九轮优化方案

## 总体判断

修复模型自我介绍与补全列表交互，按子问题逐个推进。补全列表重构参考 Codex 的布局与样式。

## 实施顺序（子问题）

### 9.1 系统提示词去身份宣称

- `src/core/prompts/agent.md`：删除第一行「你是一个面向当前工作区的 Coding Agent」，保留 5 条行为规则
- 不注入模型名，模型用自身训练认知回答身份问题

### 9.2 补全列表布局重构（底部区域）

- `screen.py`：
  - 布局改为 `logo + 对话区 + 输入栏 + 底部区域`，底部区域在输入栏下方
  - 底部区域二选一：无补全显示状态栏，补全 active 显示 CommandPicker 列表
  - 移除 CompletionsMenu 浮层与状态栏隐藏方案
- 新增 `command_picker.py`：CommandPicker（单选列表，命令名 + 描述，选中亮青 `›` 前缀，滚动跟随）
- 监听 `buffer.on_completions_changed`：补全状态变化时把匹配项渲染到底部区域
- `↑/↓` 选择、Enter 应用并提交、Tab 应用不提交（沿用现有行为，选中状态由 CommandPicker 管理）

### 9.3 选择器去圆圈

- `choice_picker.py`：去掉 ●○ 标记，选中行用 `›` 前缀，未选中行空两格

### 9.4 余额每轮刷新

- `balance.py` / `main.py`：balance provider 传入 `run_chat`
- `ui.py`：每轮对话结束后异步重新查询余额，更新状态栏（余额改为动态 provider 读取）
- 刷新失败保留旧值，不闪断显示 unavailable

## 测试计划

- 提示词：agent.md 无身份宣称（静态内容断言）
- CommandPicker：渲染 name + description、选中亮青 `›`、滚动跟随、↑/↓ 选择
- 底部区域：补全 active 显示列表、否则显示状态栏、布局位置在输入栏下方
- 选择器：无圆圈、`›` 前缀
- 余额：每轮刷新调用、失败保留旧值

## 验收标准

- 模型能按自身认知自我介绍
- 补全列表在输入栏下方（布局式），对话区被挤占，状态栏被替换
- 补全列表单选样式，选中亮青 `›`，未选中默认色
- 选择器无圆圈
- 每轮对话后余额刷新，失败保留旧值
- `uv run pytest` 全部通过

## 明确不做

- 在系统提示词中注入模型名（换模型会露馅）
- 补全列表的多列布局（Codex 的两段 name + description 单列即可）
