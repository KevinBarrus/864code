# 问题 1：从可运行原型走向可靠的 Coding Agent

## 发现来源

本问题整理自一次对当前项目的整体检查，并结合当前源码核对了 `ui.py`、`context.py`、`session_persistence.py`、`session_store.py`、`agent_loop.py`、工具模块和 `evaluation/`。

## 总体判断

当前项目已经具备完整的最小链路：模型对话、Session、工具调用、上下文压缩、异常处理和评测。当前主要问题不是模块缺失，而是部分模块之间的边界在异常场景下没有形成闭环。

“不是长期记忆”“暂时没有向量检索”不属于当前缺陷。当前 Memory 的准确定位是会话历史管理，继续引入长期记忆会偏离简洁目标。

## 问题合理性评估

### P0：应优先修复

1. **压缩上下文后，本轮消息可能无法持久化**

   评价成立。`ui.py` 使用 `result.messages[existing_count:]` 推断本轮增量，但 `result.messages` 是压缩后的模型上下文，不再与完整 Session 的消息数量对齐。应由 AgentLoop 明确返回本轮新增消息，持久化层不再通过数量切片推断增量。

2. **持久化失败后的消息只保存在内存**

   评价成立。当前 `_pending` 会在进程退出后丢失，属于真实的数据可靠性问题。需要把待写消息落到独立的恢复文件，并在下次启动时尝试恢复。

3. **JSONL 尾部损坏会导致整个 Session 无法恢复**

   评价成立。追加写入没有刷新策略，读取也没有区分“合法历史”和“最后一条未完成记录”。第一版只需要支持尾部半行修复或忽略，并保留中间行损坏的明确错误。

### P1：应在可靠性问题后处理

4. **上下文 fallback 没有硬预算保证**

   评价成立。当前 fallback 对系统消息和单个超大消息的预算控制不完整，摘要失败后仍可能超过阈值。必须让 fallback 最终经过预算校验，并定义不可再裁剪时的最小错误。

5. **工具输出可能造成上下文爆炸**

   评价成立。读取文件、搜索文件和命令输出都可能把大量内容直接交给模型。工具输出上限属于工具安全与上下文稳定性的共同边界，应统一处理。

6. **命令工具缺少超时和进程清理边界**

   评价成立。审批不能替代运行时资源保护。第一阶段增加超时、输出上限和取消时的进程组清理；CPU、内存和网络沙箱暂不作为当前项目的最小实现。

7. **MCP 权限与多 Provider 路由尚未真正落地**

   评价成立。当前 MCP 工具使用统一权限，且注册表按名称全局唯一，无法支持不同 Provider 提供同名工具。应先完成 Provider 身份参与注册、查找和执行路由，再细化权限映射。

8. **取消时可能遗漏已经发生的工具调用链**

   评价成立。模型回复的部分文本会保存，但工具调用和工具结果需要和取消状态一起保存，保证恢复后的历史能够解释已发生的文件修改。

9. **评测结果仍偏向模块回归，能力指标含义需要收紧**

   评价基本成立。当前离线场景主要验证执行链路，不能单独证明模型完成真实任务；`memory` 场景也需要覆盖 Session 重启和压缩恢复。真实在线评测应继续保留，但报告必须区分模块回归、真实任务和环境失败。

10. **Baseline 没有真正比较性能指标**

    评价成立。当前 baseline 保存了部分延迟字段，但回归判断主要检查通过与否。第一阶段至少比较任务成功率、P95 延迟、模型请求次数和压缩次数，并记录模型与评测配置标识。

11. **在线评测吞掉了错误上下文**

    评价成立。不能只保留统一的 `runner-error`，至少要记录错误类别、阶段和原始异常文本，避免把环境故障误判为 Agent 能力失败。

12. **默认 `pytest` 不能稳定收集根目录 `evaluation`**

    评价成立。这是工程入口问题，应该让标准测试命令在干净环境下直接覆盖全部测试。

### 暂不作为当前问题处理

- 精确 tokenizer、服务端 usage 校准和不同模型的特殊 Token：当前先保留可解释估算，并补充协议与工具 Schema 的固定开销；只有真实超限或指标偏差达到阈值时再接入 tokenizer
- 摘要事实自动验证：先通过结构化摘要、最近工具链和硬裁剪降低风险，不立即引入第二次事实审查模型
- 只读工具并发、任务总时限、重复调用检测：属于性能与调度增强，不阻塞当前可靠性闭环
- TUI 全量状态面板、文件变更摘要和分页：属于交互增强，先保证错误、取消和持久化降级有清晰提示
- 完整 CPU、内存、网络隔离：依赖运行环境，当前项目先实现超时、输出限制和进程清理
