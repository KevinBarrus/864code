# 上下文管理

## 当前状态

第一版和第二版核心上下文压缩已经完成，完整自动化测试通过 151 个测试。正式结束第二版前，还需要完成一次真实多轮验证

## 下一步目标

优先完成 `pi-gap.md` 中的真实验证，再根据项目需要逐项补齐与 Pi 的上下文设计差距

## 已完成的最小实现顺序

1. 区分持久化历史、运行时记忆和模型请求上下文
2. 新增独立的 Context Manager
3. 为模型请求设置 Token 预算
4. 保留完整工具调用链和最近有效消息
5. 对普通历史和单轮超大消息进行摘要压缩
6. 支持累计摘要和文件操作信息
7. 支持 compaction 持久化、恢复和失败兜底
8. 增加上下文压缩和恢复测试

## 当前暂不实现

- 向量数据库
- 语义检索
- 复杂 Token 预测
- 动态控制器
- Session 会话树和分支摘要
- Agent 内部消息到模型消息的独立转换管线
- 扩展状态和更丰富的压缩状态

## 第一版和第二版验收结果

- Session 历史不会被直接修改
- 模型请求可以获得独立的上下文消息列表
- 超出预算时能够摘要、裁剪并进行失败兜底
- 未超出预算时上下文内容保持完整
- 连续压缩后能够恢复累计摘要和文件操作列表
