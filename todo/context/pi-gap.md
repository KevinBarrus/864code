# 上下文管理后续工作

## P0：第二版正式验收

- [ ] 完成一次真实多轮上下文验证
  - [ ] 多轮普通对话并触发压缩
  - [ ] 使用超大消息或超大工具结果
  - [ ] 读取并修改文件
  - [ ] 触发多次累计摘要
  - [ ] 退出后恢复 Session
  - [ ] 验证任务目标、关键决策和文件操作信息仍被模型记住
- [ ] 记录真实验证结果和关键指标
  - [ ] 压缩前后 Token 估算
  - [ ] 摘要压缩比例
  - [ ] 多次压缩后的关键信息保留情况
  - [ ] Session.restore 前后模型可见上下文一致性

## P1：补齐 Pi 的上下文管线

- [ ] 区分 Agent 内部消息和模型协议消息
- [ ] 增加独立的上下文转换流程
  - [ ] `AgentMessage[] → transform_context`
  - [ ] `transform_context → convert_to_model_messages`
- [ ] 让 Session 可以保存 UI、扩展和压缩相关信息，但只向模型发送必要消息

## P1：增强 Session 和压缩能力

- [ ] 将线性 Session 边界升级为稳定消息 ID
- [ ] 支持 `parent_id` 和会话分支
- [ ] 支持从历史节点创建分支会话
- [ ] 增加分支摘要和分支切换后的上下文重建
- [ ] 支持更丰富的压缩记录类型，而不只使用单一 compaction 记录

## P2：改进预算和状态管理

- [ ] 评估从字符数估算升级为更接近模型的 Token 估算
- [ ] 按模型上下文窗口自动读取或校准预算
- [ ] 评估摘要、工具结果和扩展状态的统一状态恢复
- [ ] 维护比文件路径更丰富的工具操作摘要

## 设计边界

- 不因为对标 Pi 引入向量检索
- 不删除或修改原始 JSONL 历史
- 不在 ContextManager 中硬编码具体工具名称
- 每项增强先补测试，再修改生产代码
