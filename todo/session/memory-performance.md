# 运行期会话历史性能

## 当前边界

`Session` 在进程内保留完整消息历史，并在读取和构建上下文时复制消息列表。这是当前 Session 恢复、压缩索引和 JSONL 持久化的一致性来源，不是正确性缺陷

## 何时处理

先在代表性长会话上进行性能剖析；满足任一条件后再立项：

- 单轮读取与构建上下文的额外耗时超过 200 ms
- 进程常驻内存超过 500 MiB 且主要由会话消息占用
- 单会话达到 10,000 条消息并出现明显交互卡顿

## 后续方向

- 保持 JSONL 为完整历史的唯一持久化事实来源
- 优先评估不可变消息视图，减少无意义的列表复制
- 仍不足时再按压缩边界按需加载历史片段
- 每种方案都需验证恢复、压缩索引和工具消息顺序不变

## 非目标

- 不以消息数量阈值直接触发自动删除历史
- 不在未完成剖析前引入数据库、缓存层或新的记忆系统
